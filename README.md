# En lice

A dialogue app where people are matched with a thoughtful opponent and scored on
curiosity and constructiveness. Backend + hosting on **PocketBase**, custom SPA
frontend, deployed on a single **Hetzner** box at **enlice.eu**. Scoring (Anthropic
API) is deferred behind a seam.

This repo is **Phase 0** of the build plan: the deployable skeleton.

## Layout

```
pb_migrations/   versioned schema (applied on start)
pb_hooks/        server logic, one file per domain
  lib/           the swappable seams: notify.js, scoring.js (stubbed)
pb_public/       built SPA (generated by the frontend build)
frontend/        Vite + React SPA source (builds into ../pb_public)
scripts/         seed.mjs — topics + fake users for testing matchmaking
deploy/          setup-server.sh (provision) + deploy.sh (push & restart)
```

## Phase 0 run order

1. **Provision the server** (on a fresh Ubuntu 24.04 Hetzner box, as root). Use
   `linux_arm64` on a CAX server, `linux_amd64` on CX/CPX:
   ```
   ./deploy/setup-server.sh enlice.eu 0.39.2 linux_arm64
   ```
   Point an A record for `enlice.eu` at the box, then open `https://enlice.eu/_/`
   and create the first **superuser** (this is your admin/moderator login).

2. **Configure email** in the dashboard → Settings → Mail (Brevo/Mailgun/SES) —
   the in-app + email notifications need real SMTP.

3. **Deploy the code** from your machine (applies the schema migration on restart):
   ```
   ./deploy/deploy.sh root@<server-ip>
   ```

4. **Seed test data**:
   ```
   cd scripts && npm install
   PB_URL=https://enlice.eu PB_ADMIN_EMAIL=you@example.com \
   PB_ADMIN_PASSWORD=*** SEED_USERS=20 npm run seed
   ```

5. **Verify (done criteria):**
   - `https://enlice.eu/api/health` returns `{ "status": "ok" }`
   - the dashboard shows all collections (topics, opinions, dialogues, …)
   - the SPA loads over HTTPS and you can navigate the screen shells

## Local development

```
cd frontend && npm install
VITE_PB_URL=https://enlice.eu npm run dev    # SPA against the live backend
```

## What's stubbed (and where it gets real)

- **Scoring** — `pb_hooks/lib/scoring.js` returns fixed numbers. Phase 2 swaps the
  body for one Anthropic API call at dialogue end.
- **Notifications** — `pb_hooks/lib/notify.js` writes the in-app row. Phase 1 adds
  email dispatch.
- **Matchmaking / dialogue / onboarding / moderation hooks** — skeleton files with
  the intended hooks commented; filled in Phase 1.
- **Frontend screens** — routed but unstyled. Phase 1 builds the real UI from the
  design spec.

## Security note

PocketBase has no encryption at rest, and this stores political opinions. Before a
real launch, put `pb_data` on an encrypted volume.

## Phase 1 status (Kiln)

The frontend is now the real **Kiln** design language, not shells:
`theme.js` (tokens) + `ui.jsx` (Screen, Card, Button, Pill, Meter, Avatar, Field, Scale),
`auth.js` (reactive auth), and a gated router that funnels new users
**Inscription → Opinions → Accueil**.

Working end-to-end with the current rules + hooks:
- **Inscription** — SSO (Google/Apple), pick pseudonym, accept the charte.
- **Opinions** — the 5-point form; the **onboarding hook** flips `onboarding_complete`.
- **Accueil** — join/leave the matchmaking queue; lists your active dialogues.
- **Dialogue** — async thread, send on your turn, flag a behaviour (realtime).
- **Profil** — pseudonym + your opinions; **Bilan/Classement** styled, awaiting scoring.

Still to build — the **Phase 1 backend increment** (server logic, not screens):
- the **matcher** (clash + common ground, relax-when-small, never re-match, cap),
- **turn-flip + reply notifications** on new messages,
- **time-limit expiry** cron,
- **leave-dialogue** route, and the **signup ban-check**.

Until those land: sign-in, the opinion form, joining the queue, and reading/sending
within a dialogue all work; actual pairing and turn-advancing need the matcher and
dialogue hooks.

> Setup note: enable Google/Apple OAuth2 in the PocketBase dashboard
> (Settings → Auth providers) for Inscription to work.
